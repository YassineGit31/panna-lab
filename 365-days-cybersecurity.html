02 / SECURITY ENGLISH

The vocabulary of the field, five minutes a day

This track assumes your general English is already workable and focuses narrowly on technical vocabulary — advisories, CVEs, incident reports, and vendor documentation are almost always written in English first.

MIN 1

3 terms from today's topic — meaning, example, pronunciation, common mistake.

MIN 2

Read one paragraph of a real advisory, CVE description, or doc page using today's terms.

MIN 3

Say one sentence out loud, explaining today's concept as if to a non-technical manager.

MIN 4-5

Write 2–4 sentences in the style of an incident note, then self-correct with ❌ / ✅.

Incident-note correction format

❌ "The attacker was accessing to the server since two days."

✅ "The attacker had been accessing the server for two days."

Why: "access" isn't followed by "to," and an ongoing past action up to another point needs the past perfect continuous. Only meaningful mistakes get corrected — clarity first, polish second.

Why this matters professionally

Most CVEs, vendor security bulletins, MITRE ATT&CK descriptions, RFCs, and certification exams (Security+, CEH, OSCP, CISSP) are written in English. Building this vocabulary alongside the concepts means you can go straight to primary sources instead of waiting for a translation.

Every 30 days: the monthly test

  • 8–10 multiple-choice questions across the month's domains
  • 4–5 short-answer questions requiring a real explanation
  • 1–2 practical problems (read a log line, identify a flaw, design a control)
  • A Security English section: term recall + one corrected incident note
  • 2–3 cross-domain questions (e.g., how a crypto weakness enables an app-security exploit)
